# ADR

## ADR-0001 — UI 프레임워크를 AdminLTE 3 / Bootstrap 4 에서 Bootstrap 5.3 으로 옮긴다

**상태**: Accepted (2026-09-25)

**맥락**

현재 레이아웃은 AdminLTE 3.2.0 + Bootstrap 4.6.2 + jQuery 3.6.0 이다. AdminLTE 는 관리자 대시보드용이고 이 사이트는 공개 안내 사이트라, 사이드바·컨트롤바·박스 위젯 등 쓰지 않는 것이 대부분이다. 실제로 `main.css` 는 AdminLTE 가 `.wrapper` / `.content-wrapper` 에 박아둔 배경을 `!important` 로 되돌리는 데 지면을 쓰고 있다. Bootstrap 4 는 2023-01 EOL 이고 다크 모드 개념이 아예 없어서, 드롭다운·탭·alert·표의 다크 대응을 전부 손으로 짜야 한다. 지금 다크가 절반쯤 깨져 있는 근본 원인이 이것이다.

**결정**

Bootstrap 5.3 의 color modes (`data-bs-theme`) 로 옮기고 AdminLTE 와 jQuery 를 걷어낸다. 5.3 은 모든 컴포넌트가 라이트/다크를 내장하고 있어, 지금 손으로 짠 테마 토글 스크립트도 공식 문서 스니펫으로 대체된다.

**근거**

- 컴포넌트 다크 대응이 프레임워크 몫으로 넘어간다 — 이 작업의 목적 자체다.
- jQuery / AdminLTE 두 개의 런타임 의존이 사라진다. 현재 CDN 4곳에 의존하는데 그중 둘이 없어진다.
- 클래스명 변환은 기계적이다: `ml-*`→`ms-*`, `mr-*`→`me-*`, `float-right`→`float-end`, `data-toggle`→`data-bs-toggle`, `text-muted`→`text-body-secondary`.
- 3개로 복붙된 다크 팔레트 블록(`main.css:35`, `:356`, `:381`)이 하나로 정리된다.

**버리는 것**

AdminLTE 의 navbar 스타일에 기대던 부분은 다시 짜야 한다. 그러나 현재도 `main.css` 에서 대부분 덮어쓰고 있어 실질 손실은 작다.

**대안**

- *Bootstrap 4 유지 + 다크 직접 보수* — 지금의 반복이다. EOL 프레임워크에 손으로 짠 테마를 계속 얹는 셈이라 기각.
- *Pico CSS (클래스리스, 자동 라이트/다크)* — 가볍지만 탭·드롭다운을 직접 만들어야 한다. 접속 안내의 OS 탭이 이 사이트의 핵심 UI 라 기각.
- *Tailwind* — 빌드 파이프라인이 붙는다. Jekyll + GitHub Pages 의 무빌드 장점을 잃어 기각.

## ADR-0002 — 배색은 Radix Colors 스케일을 그대로 가져다 쓴다

**상태**: Accepted (2026-09-25)

**맥락**

현재 라이트 팔레트는 생성된 값이고 다크는 급조된 값이라, 양쪽 모두 명암비가 설계되지 않았다. 색을 하나 고칠 때마다 라이트/다크 두 벌을 각각 눈으로 맞춰야 하는데 이게 지속되지 않는다. 직접 팔레트를 설계하는 대신, **라이트/다크가 쌍으로 검증된 스케일을 그대로 쓴다**는 것이 이 결정의 전제다.

**결정**

Radix Colors 의 12단계 스케일을 vendor 로 받아 토큰의 출처로 삼는다. 중립은 `slate`, 브랜드 계열은 `blue` 를 쓴다. Bootstrap 5.3 의 시맨틱 변수를 이 스케일에 매핑하고, 사이트 코드는 Bootstrap 변수만 참조한다.

Radix 스케일은 단계마다 역할이 정해져 있고 라이트/다크에서 **같은 단계가 같은 역할**을 하도록 설계되어 있다. 이게 "한 번에 해결"의 실체다.

| 단계 | 역할 | 매핑할 Bootstrap 변수 |
|---|---|---|
| 1–2 | 페이지 / 카드 배경 | `--bs-body-bg`, 카드 배경 |
| 3–5 | 컴포넌트 배경, hover | `--bs-tertiary-bg` |
| 6–8 | 테두리 | `--bs-border-color` |
| 9–10 | 솔리드 브랜드 색 | `--bs-primary` |
| 11 | 보조 텍스트 (배경 위 4.5:1 보장) | `--bs-secondary-color` |
| 12 | 본문 텍스트 | `--bs-body-color` |

**근거**

- 명암비가 스케일 자체에 설계되어 있다. `#888` / `#aaa` / `#444` 를 눈으로 고르던 것을 그만둔다.
- 다크 스케일이 라이트와 짝으로 제공되므로 다크를 따로 설계하지 않는다.
- 순수 CSS 커스텀 프로퍼티 파일이라 빌드 도구가 필요 없다.

**구현 제약**

- **`light-dark()` CSS 함수를 쓰지 않는다.** 이 함수는 Chromium 123 / Safari 17.5 이상이라 구버전 Samsung Internet 에서 동작하지 않는다. 이 개편의 출발점이 삼성 단말 다크 이슈인데 정작 삼성 브라우저에서 안 먹는 문법을 쓰면 본말전도다. `[data-bs-theme="dark"]` 선택자 아래에서 변수를 재정의하는 방식으로 간다 — 전 브라우저에서 동작한다.
- **hex 값을 기억으로 적지 않는다.** Radix CSS 파일을 실제로 받아서 넣는다 (CLAUDE.md "숫자는 측정해서 쓴다").
- CDN 이 아니라 `assets/css/vendor/` 에 커밋한다 (CLAUDE.md CDN 정책).
- eduroam 브랜드 네이비(`#003d7a`)는 라이트 navbar/히어로의 **면 색**으로만 남긴다. 텍스트·아이콘 강조색으로 쓰던 자리는 `blue-11` 로 옮긴다 — 네이비는 다크 카드 위에서 명암비 1.43 으로 읽히지 않는다.

**대안**

- *Bootstrap 5.3 기본 팔레트만 사용* — 결정 수는 가장 적지만 "배색을 팍 바꾼다"는 요구에 못 미치고, 브랜드 계열 색은 여전히 직접 골라야 한다.
- *Open Props* — 라이트/다크 쌍 보장이 Radix 만큼 명시적이지 않다.
- *USWDS / GOV.UK 팔레트* — 공공 영역 검증은 강하지만 다크 토큰이 완결되어 있지 않다.

## ADR-0003 — 반응형은 Bootstrap 그리드에만 맡기지 않는다

**상태**: Accepted (2026-09-25)

**맥락**

`assets/css/main.css` 에 반응형 미디어 쿼리가 **0개**다. `@media` 는 `prefers-color-scheme` 두 개뿐이고, 화면 폭 대응은 전부 마크업의 `col-6 col-md-3` 같은 그리드 클래스에 의존한다. 그래서 폭이 좁아져도 카드 패딩(32px), 폰트 크기, 섹션 여백이 데스크탑 값 그대로다. 360px 화면에서 본문 가용 폭이 270px 남짓이 되는 이유다.

**결정**

`sm` / `md` 구간 미디어 쿼리를 도입해 패딩·타이포 스케일을 낮춘다. 한국어 사이트이므로 `word-break: keep-all` 을 전역에 넣어 어절 중간 줄바꿈을 막는다.

**근거**

그리드 클래스는 열 배치만 바꾼다. 여백과 글자 크기는 그리드가 모르는 영역이고, 지금은 아무도 안 보고 있다.
